100% Local Processing

All data processing happens entirely on your local machine. Your files and data never leave your computer.

Data Processing

All processing is local:

  • File uploads are sent only to http://127.0.0.1:5000 (localhost)
  • All analysis uses pandas running on your machine
  • Results are stored temporarily in memory, then deleted
  • Temporary files are stored locally and automatically cleaned up
  • All communication stays within your local network

What We Don't Do

Your data is never:

  • Sent to cloud services or external APIs
  • Stored in databases
  • Logged or tracked
  • Shared with third parties
  • Transmitted over the internet
  • Analyzed for marketing or analytics

External Connections

The only external connections are for JavaScript libraries (code only, no data):

Chart.js
Chart rendering library (cdn.jsdelivr.net)
jsPDF
PDF generation library (cdnjs.cloudflare.com)
html2canvas
Canvas conversion library (cdnjs.cloudflare.com)

Important: These are code libraries only. They run in your browser to create visualizations and PDFs. They do not receive or transmit any of your data. They are standard, open-source libraries used by millions of applications.

Data Lifecycle

  1. Upload: File is temporarily saved to local uploads/ folder
  2. Processing: File is read into memory using pandas
  3. Analysis: All calculations happen in memory
  4. Results: Analysis results sent to browser (via localhost)
  5. Cleanup: Original file deleted immediately after processing
  6. Memory: DataFrames explicitly deleted from memory

Privacy Guarantee

Your Data Never Leaves Your Machine

All data processing occurs entirely within your local environment. Files are processed, analyzed, and results are displayed - all without any external transmission. Temporary files are automatically deleted, and no traces of your data remain after processing.

Security Features Implemented

Security Measures
  • Secure Session Keys: Generated using secrets.token_hex(32) (64-character cryptographically secure random string)
  • Session Lifetime: 1 hour maximum, automatically expired
  • Rate Limiting: 10 requests per 60 seconds per IP address (prevents DoS attacks)
  • File Upload Validation: File extension and MIME type checking
  • Path Traversal Protection: secure_filename() sanitizes all file paths
  • File Size Limits: Maximum 500MB per file upload
  • Input Validation: Chunk size limits (1 to 1,000,000 records), filename sanitization
  • Secure Session IDs: Generated using secrets.token_hex(8) with timestamps
  • Automatic Cleanup: Temporary files deleted immediately after processing
  • Memory Management: DataFrames explicitly deleted from memory after use
  • No Persistent Storage: No database, no file system persistence of user data

Data Processing Architecture

Processing Flow:

  1. Upload: File received via HTTP POST, saved to uploads/ directory with session ID prefix
  2. Validation: File extension (.xlsx, .xls, .csv), MIME type, and size checked
  3. Processing: File read into pandas DataFrame in memory
  4. Analysis/Transformation: All operations performed in-memory using pandas
  5. Output: Results written to output/ directory (temporary)
  6. Cleanup: Original upload file deleted, output files available for download then auto-deleted

Network Architecture

Network Configuration
  • Server Binding: 127.0.0.1:5000 (localhost only, not accessible from network)
  • Protocol: HTTP (not HTTPS - localhost only, no external access)
  • Connection Types: HTTP POST (file uploads), HTTP GET (downloads), SSE (progress updates)
  • External Connections: Only for CDN JavaScript libraries (code download, no data)
  • No Outbound Data: Application never sends user data to external servers

Session & State Management

Session Storage:

  • Progress Queues: In-memory Python Queue objects, keyed by session ID
  • Analysis Results: In-memory dictionary, auto-expires after 1 hour
  • Rate Limit Tracking: In-memory defaultdict, per-IP address
  • Session IDs: Format: {timestamp}_{16-char-hex} (e.g., "20251117_010432_a1b2c3d4e5f6g7h8")
  • Cleanup Thread: Background daemon thread runs every 5 minutes to remove expired sessions

Data Flow & Memory Management

Memory Handling:

  • DataFrames: Created in memory, explicitly deleted with del df after processing
  • File Reading: pandas reads entire file into memory (no streaming for Excel files)
  • Analysis Results: Stored in-memory dictionary, maximum 1 hour retention
  • Progress Updates: Thread-safe Queue objects, cleaned up after session completion
  • No Memory Leaks: All objects explicitly deleted, cleanup threads run periodically

Error Handling & Logging

  • Error Responses: JSON error messages with appropriate HTTP status codes (400, 404, 429, 500)
  • Exception Handling: Try-catch blocks around all file operations
  • Logging: Console print statements for debugging (no persistent logs)
  • Error Cleanup: Temporary files deleted even on error conditions
  • Stack Traces: Full traceback printed to console for debugging (not exposed to client)

Threading & Concurrency

  • Background Processing: File operations run in daemon threads
  • Thread Safety: Queue objects for thread-safe communication
  • Cleanup Thread: Daemon thread runs every 5 minutes to clean expired sessions
  • No Race Conditions: Each session has isolated queue and file paths
  • Thread Count: One thread per active file processing operation

Compliance & Audit Considerations

Security Compliance Notes
  • No Data Persistence: No databases, no long-term file storage
  • No User Authentication: Single-user local application
  • No Audit Logging: No persistent logs of user actions or data access
  • No Data Transmission: All processing local, no external API calls with data
  • Source Code Visibility: All code is visible in app.py for review
  • Dependency Transparency: All dependencies listed in requirements.txt
  • No Encryption: Files stored unencrypted in temporary directories (localhost only)
  • No Network Encryption: HTTP only (acceptable for localhost-only access)

Known Limitations

  • File Size: Limited by available RAM (entire file loaded into memory)
  • Concurrent Users: Not designed for multi-user access (single local instance)
  • No Authentication: Anyone with localhost access can use the application
  • No Encryption: Files stored unencrypted during processing
  • No Backup: No data persistence or recovery mechanisms
  • CDN Dependency: Requires internet connection for initial JavaScript library loading (code only)

Questions?

  • Review the source code (all processing is visible in app.py)

  • Run the application in an isolated environment if needed
